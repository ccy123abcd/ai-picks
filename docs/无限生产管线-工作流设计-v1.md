# AI-PICKS 无限生产管线（工作流设计 v1）

> 试点验证：2026-10-16 已跑通 `best-budget-flagship-phone-2026`（Pixel 9a / Galaxy A56 / Nothing Phone 3a），
> JSON → generate.py → human/ai 双版本页面全链路可用。

## 管线六步

```
每天凌晨自动跑：

① 选题
从品类清单取下一个没做的，按高决策成本优先排序。
手机类单独高频（每月刷新），其他品类按季度。

② 抓料（脚本，零 token）
- YouTube 测评：yt-dlp 抓 transcript（轻量请求，加 delay）
- 专业评测站：RTINGS / PhoneArena / Notebookcheck 等，直接抓（加 delay）
- Amazon 参数：走加拿大住宅 IP（现有分工，不变）
- 手机规格库：GSMArena 结构化数据

③ 提炼（27B，唯一烧模型的一步）
输入：② 的原始材料
输出：data/best-[品类]-2026.json（严格按下方 JSON 格式）
提示词见本文档附录。

④ 渲染（现有脚本，不用改）
python3 scripts/generate.py → output/human/ + output/ai/

⑤ 质检（脚本自动）
- 字段完整性：top_pick / products / review_sources 非空
- 格式校验：top_pick 为对象、aggregate_rating 为对象、review_sources 为对象数组
- 空话检查：summary 禁止"性价比高""值得购买"等
- ASIN 检查：只有 VERIFIED_ASINS 里的才渲染购买按钮
- 图片检查：top_pick.image 引用的文件必须在 images/ 目录存在，否则页面破图。如无图片，留空字符串，模板会跳过渲染。
  图片来源：用 image-search 找官方产品图（Google Store / Samsung 官网优先），curl 下载到 images/，命名规范 `[slug].jpg`。

⑥ 发布
git add + commit + push → 自动部署到 aivaultpro.com
```

## 本地局限性（龙岩 4070 12GB）

| 限制 | 影响 | 对策 |
|---|---|---|
| 27B Q4 约 16GB，装不进 12GB 显存 | 必须 offload 部分到内存，速度降到 5-10 tok/s | 夜间批处理，不赶时间；一张卡约 2000 token，7 分钟/张，一夜可产约 60 张 |
| Ollama 与 Hermes 共用 | Hermes 的 AnythingLLM 也在用 Ollama embedding | 管线跑在凌晨 2-6 点，避开 Hermes 高峰；或用 OLLAMA_HOST 隔离端口 |
| yt-dlp 抓 YouTube 有频率限制 | 太快会被限流 | 每个品类间隔 30 秒以上；transcript 是轻量请求，风险低于下视频 |
| Amazon 反爬凶 | 云 IP 直接 403 | 沿用现有分工：Amazon 走加拿大住宅 IP |
| 手机品类更新快 | 月度刷新压力大 | 手机单独 cron，每月 1 号跑；其他品类季度跑 |

## 附录：提炼提示词（27B 用）

```
你是一个产品评测聚合专家。你的任务是阅读多个真实测评人的观点，提炼出一份结构化的商品对比卡。


你会收到以下材料：
1. YouTube 测评视频的文字稿（多个博主）
2. 专业评测网站的文章摘要
3. 产品参数表（GSMArena / Amazon）


1. 找出测评人之间的共识：大家都认同的优点/缺点
2. 找出分歧：有人夸、有人骂的点，分别是谁说的
3. 把技术参数翻译成人话：不要写"500mm/s"，要写"打印速度是普通机的 X 倍，打个手办从 8 小时缩到 3 小时"
4. 每个产品一句话说清适合谁：不要"性价比高"这种空话，要"适合第一次买 3D 打印机、不想折腾的人"


严格输出以下 JSON，不要加任何解释文字：

{
"page_title": "Best [品类] 2026",
"h1": "Best [品类] 2026",
"meta_description": "一句话描述，150 字以内",
"slug": "best-[品类]-2026",
"updated_date": "2026-10-16",
"top_pick": {
"name": "产品全名",
"brand": "品牌",
"image": "../images/[slug].jpg",
"platforms": ["amazon"],
"price_display": "$xxx-$xxx",
"price_value": 449.0,
"reason": "2-3 句话讲清为什么它是综合最推荐，人话",
"affiliate_link": ""
},
"common_pros": ["所有测评人都认同的优点1", "优点2"],
"common_cons": ["所有测评人都认同的缺点1"],
"products": [
{
"name": "产品全名",
"best_for": "一句话说清适合谁，具体场景",
"price_range": "$xxx-$xxx",
"summary": "2-3 句话，讲清这产品的定位和最大卖点，人话",
"specs": {
"参数名": "人话解释，不只抄数字"
},
"recommended_by": "X/Y reviewers",
"platforms": ["amazon"]
}
],
"review_sources": [
{"channel": "博主/网站名", "title": "视频/文章标题", "url": "链接"}
],
"aggregate_rating": {"best": 5, "count": 0, "value": 4.4}
}


- 只写材料里有的东西，不要编造参数和评价
- recommended_by 必须数清楚，几个博主推荐就写几/几
- summary 里不许出现"性价比高""值得购买"这种空话，必须具体
- specs 的值必须是人话解释，不能只贴原始数字
- 如果测评人之间有分歧，在 summary 里点出来是谁什么观点
- top_pick 必须是对象（含 name/brand/reason 等），不是字符串
- affiliate_link 留空，除非该 ASIN 已人工核验加入 VERIFIED_ASINS
```
